Fixing stale API responses in a ride-hailing appإصلاح ردود الـ API القديمة في تطبيق توصيل

Problemالمشكلة
When the user changed the destination quickly, an older response could arrive after a newer one and overwrite it, showing a wrong route and ETA.عند تغيير الوجهة بسرعة، كان الرد الأقدم يصل بعد الأحدث ويكتب فوقه، فيظهر مسار ووقت وصول خاطئان.
What I didما فعلته
Found the cause (responses finishing out of order) and made sure only the latest request can update the screen. Added handling for invalid coordinates, timeouts and a retry UI for ETA errors.حدّدت السبب (انتهاء الردود بترتيب مختلف) وجعلت آخر طلب فقط هو الذي يحدّث الشاشة. وأضفت معالجة للإحداثيات غير الصالحة والمهلات وواجهة إعادة المحاولة.
Resultالنتيجة
Wrote automated tests for network failures and request races, and QA verified the fix.كتبت اختبارات آلية لأعطال الشبكة وتعارض الطلبات، وأكّد فريق الجودة الإصلاح.

Offline chat with an outbox and automatic retryمحادثة تعمل دون إنترنت مع صندوق إرسال وإعادة محاولة تلقائية

Problemالمشكلة
Users lose connection often, and messages typed offline must not be lost.يفقد المستخدمون الاتصال كثيراً، ويجب ألا تضيع الرسائل المكتوبة دون إنترنت.
What I didما فعلته
Stored chat history locally and added an outbox: unsent messages wait locally, retry automatically, and sync when the connection returns.خزّنت سجل المحادثة محلياً وأضفت صندوق إرسال: الرسائل غير المرسلة تنتظر محلياً وتُعاد تلقائياً وتتزامن عند عودة الاتصال.
Resultالنتيجة
The chat works offline and users see the state of each message.تعمل المحادثة دون إنترنت ويرى المستخدم حالة كل رسالة.
